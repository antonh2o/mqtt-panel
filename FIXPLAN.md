## Задача 1 — Народмон: последние значения не обновляются

Скрин: `photo_5197493809732852590_y` (v0.2.80, снят в 06:51):

- у большинства карточек метка значения «06:42:59» — на 9 минут старше скриншота,
  при минутном опросе должна быть ≈06:50;
- «Дача Улица температура»: значение 0.8 °C, метка 20.11 14:13:15 (трое суток),
  график — окно 21.11 06:53 → 22.11 06:48, т.е. история этой карточки не
  обновлялась больше суток;
- статус подключения «✓ 14 ч 15 мин» — сервис жив и не терял статус.

### Диагноз (по коду 0.2.80)

1. **Пауза значений на весь пакет истории (регрессия A3).** `loadNarodmonChartHistory`
   ставит `NarodmonService.pollingPaused = true` на время ВСЕГО пакета загрузки
   историй. При отказах платформы пауза между запросами растёт 21→42→84→120 с;
   пакет из 8 карточек длится 5–15+ минут — всё это время значения не опрашиваются
   вовсе, карточки замирают. На скрине: дашборд открыт ~06:42 (последний опрос
   06:42:59), пакет ещё не закончился к 06:51.
2. **«Улица» отдельно.** Платформа либо не отдаёт этот датчик в `sensorsNearby?my=1`,
   либо отдаёт с меткой времени от 20.11 (запись датчика на платформе не обновляется).
   В журнал пишутся только НЕудачи опроса — успешный опрос не логируется, поэтому
   отличить «платформа молчит по датчику» от «приложение не опрашивает» невозможно.

### Фикс

1. Убрать полную паузу опроса значений на время пакета: минутный опрос значений
   идёт всегда; история троттлится 30 с между запросами (2 запроса истории/мин +
   1 запрос значений/мин = 3 запроса/мин — в рамках лимита платформы). Пакет
   историй станет на ~30% длиннее, зато значения свежие всегда.
2. Диагностика в журнал (`mqtt-panel.log`, не чаще раза в 5 минут) при успешном
   опросе: сколько датчиков вернул `sensorsNearby`; каких датчиков из панелей нет
   в ответе (id + имя); какие пришли БЕЗ ЗНАЧЕНИЯ (value=null); какие датчики
   платформа отдаёт со временем старше 1 часа (id, метка платформы, возраст).

### Проверка на стенде (эмулятор + реальный ключ, 23.11 08:24–08:32)

- журнал: `sensorsNearby` каждую минуту (08:24:45…08:30:45) ПАРАЛЛЕЛЬНО с пакетом
  истории (~30 с между запросами) — при 0.2.80 опрос замер бы на весь пакет;
- метки значений шагнули 08:22:58 → 08:27:58, значения изменились
  (84.4→84.7 W, 235→239 V, 2.2→2.3 °C) — ещё до конца пакета;
- «Улица» (48194): платформа на первом опросе отдала датчик БЕЗ значения
  (карточка «—»), через минуту — со значением 0.8 °C. Устройства (ESP32)
  репортят на платформу раз в 5 минут — быстрее платформа не даст;
- диаметр пакета историй: 7 карточек ≈ 3 мин (было ~2.5 мин с паузой значений).

## Задача 2 — вид графиков «как на образце» (анатомия классического графика)

Образец: `photo_5197493809732852584_y` — анатомия matplotlib-графика: заголовок,
легенда, основная сетка (major grid), дополнительная сетка (minor grid), основные
и дополнительные тики, подписи осей X и Y.

Интерпретация для ChartView (одиночный график, мультиграфик, полный экран):

- рамка-оси вокруг поля графика (как у matplotlib);
- основная сетка по major-тикам + дополнительная (реже/тоньше) по minor-тикам;
- тики наружу на осях;
- подписи осей: X — время, Y — значение (с суффиксом панели);
- заголовок и легенда — уже есть, приводим к стилю образца.

Макет покажу скриншотом с эмулятора до выпуска; требует «утверждено».

### Реализация (23.11, ждёт «утверждено»)

ChartView (действует на график, мультиграфик и полный экран сразу):

- рамка-оси (spines) вокруг поля графика — рисуется поверх данных, как в matplotlib;
- дополнительная (minor) сетка: тонкие сплошные линии в половине шага
  major-уровней по вертикали и в промежутках четвертей по горизонтали;
- основные тики наружу: по нижнему краю на краях/четвертях, по левому —
  на «красивых» уровнях шкалы; дополнительные тики — короче, в промежутках;
- подписи осей (только полный экран, флаг axisLabels): X — «Время»
  (axis_time_label, RU/EN), Y — единицы измерения панели повёрнутой строкой
  слева от шкалы; на карточках выключено — там каждая точка высоты на счету,
  единицы уже видны в значении/легенде;
- в пустом режиме (нет данных) тоже рисуется рамка;
- легенда и заголовок уже есть (строка легенды мультиграфика с номерами
  серий и значениями; заголовок полного экрана цветом серии над значением) —
  оставлены в текущем виде, как утверждено ранее.

Проверено на эмуляторе: карточка-график, карточка-мультиграфик, полный экран
одиночного и мультиграфика, тёмная тема. Тесты зелёные.

### Наложения легенды и времени (23.11, итерация по замечанию владельца)

- **Карточка мультиграфика**: легенда — полупрозрачная плашка ПО ЦЕНТРУ верха
  поля графика; время последней передачи — плашкой в правом верхнем углу.
  Отдельных строк под графиком больше нет — карточка стала ниже, кривым
  досталась вся высота (104dp).
- **Видимость легенды**: показывается при касании графика (палец на кривой)
  и на 3 секунды после прихода показания; остальное время скрыта.
- **Легенда и время не мелькают вместе**: это одна «свежесть данных» —
  пока легенда видна, плашка времени погашена, и наоборот.
- **Карточка одиночного графика**: время передачи — плашка в правом верхнем
  углу поля графика.
- **Полный экран**: легенда по центру верха поля графика, время справа —
  обе поверх кривых (там места достаточно, показаны постоянно).
- Жесты графика (крестовина, свайп периода, пинч) работают: плашки не
  перехватывают касания.

Проверено на эмуляторе (видимая/скрытая легенда, время, полный экран).
Тесты зелёные.

### Итерация по проверке на живом конфиге (23.11, «Дача»)

- **Моргание исключено**: окно видимости отсчитывается от ПОСЛЕДНЕГО показания
  (каждое новое продлевает его) — при потоке данных чаще 3 с легенда горит
  не гасая; при редких показаниях появляется/уходит ПЛАВНЫМ угасанием 180 мс,
  без жёсткого включения-выключения.
- **Легенда не перекрывает перекрестие**: пузырь подсказки опускается ПОД
  плашку легенды, когда наезжает на неё по горизонтали (ChartView получает
  зону плашки — overlayTopRect); вне зоны пузырь ведёт себя как раньше.
- Проверено на живом стенде с конфигом владельца («Дача», mqtt.iotw.ru):
  мультиграфики «Атм давление», «Сигнал Bluetooth» (4 серии — легенда в
  4 строки читается, значения цветами серий), перекрестие поверх легенды.
  Стенд погашен (pm clear).

## Задача 3 — блокировка: сохранение состояния и плотная раскладка

Сейчас `WidgetAdapter.locked` живёт только в памяти: перезапуск приложения
снимает блокировку.

Фикс:

1. Состояние блокировки сохраняется в SharedPreferences (`dashboard/locked`)
   и восстанавливается в onCreate ДО первого бинда: карточки и меню
   отрисовываются уже в согласованном режиме (иконка замка, скрытие
   «Добавить/Переместить»).
2. В заблокированном режиме убираются внешние поля карточек (4dp в бинде
   адаптера) — карточки встают вплотную, крайние отступы RecyclerView (8dp)
   остаются, к экрану не приклеиваются. Многоточия и время карточек скрыты
   (0.2.80). При разблокировке поля возвращаются.

Проверено на эмуляторе: блокировка → force-stop → запуск — режим
восстановился, меню показывает «Разблокировать», раскладка плотная;
разблокировка возвращает поля/меню/время. Тесты зелёные.

### Итерация по замечанию владельца: артефакты углов + ужать отступы

- при нулевых полях на стыках четырёх скруглённых углов просвечивал фон
  («ромбики») — в блокировке радиус карточек обнуляется: карточки сливаются
  в ровное полотно данных (при разблокировке 12dp возвращаются);
- внутренние отступы карточек 8 → 4dp и крайние отступы сетки 8 → 4dp
  в режиме блокировки; на разблокированном дашборде всё как было.
